## Purpose

Implement only explicitly authorized tasks from an approved implementation plan.
A task may contain related edits within one objective and risk boundary; a
sequence may cover multiple identified tasks only under CORE N-07 authorization.

Work incrementally and preserve existing functionality.

## Required inputs

- Approved specification.
- Approved implementation plan.
- Explicitly authorized task ID.
- Applicable AGENTS.md instructions.

If any required input is missing, ask before editing.

## Procedure

1. Read the root AGENTS.md.
2. Read relevant project instructions.
3. Review the approved specification and plan.
4. Confirm the authorized task and its scope.
5. Inspect the current files and Git status.
6. Read relevant local framework documentation.
7. Implement only the authorized task.
8. Review the resulting diff.
9. Perform only authorized editing controls (content and scope/diff inspection).
   Keep them distinct from formal TEST; do not claim a TEST pass from editing.
10. Report the identified delivery: branch/HEAD, baseline and diff/new files,
    tasks, changed regions, editing controls, AC coverage and limitations.
11. Reassess impact under CORE N-04 if scope, consumers or uncertainty change.
    Stop dependent work under N-14; elevation never enlarges permissions.

## Safety rules

- Modify only files necessary for the approved task.
- Never implement unapproved tasks.
- Do not install dependencies without permission.
- Do not commit, push or deploy.
- Do not delete unrelated code or files.
- Preserve existing uncommitted changes.
- Do not expose secrets.
- Do not claim verification passed unless executed.
- Ask before expanding scope.

Write the report in Spanish.

### 1. Task identification

### 2. Files changed

### 3. Implementation summary

### 5. Acceptance criteria

Identify which criteria were checked,

### 6. Risks and observations

Report relevant limitations or unexpected findings.

### 7. Recommendation

State whether the task is ready for developer review.

## Completion criteria

The task is complete when the authorized change
has been implemented and reported.

Stop at every required human milestone or N-14 condition. Otherwise transition
to another identified task or TEST only when approved inputs and existing
explicit authorization cover it under CORE N-05/N-07/N-08; never request a
sufficient permission again. TEST requires an identifiable delivery without
unresolved scope deviations. Subsequent corrections require specific later
BUILD authorization under N-09. Acceptance and Git/deployment decisions remain
independent under N-15; this report grants none of them.
